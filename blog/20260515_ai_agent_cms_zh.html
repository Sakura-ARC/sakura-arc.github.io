与其发社交媒体，不如让AI更新自己的网站！
—— Antigravity×GitHub Pages

By Haru Minamo 2026-05-15

前言：为什么这个博客既不是 Note 也不是 WordPress

事实上，这篇文章仅通过聊天指令就完成了。AI 构思了文章、生成了 HTML、推送到 GitHub 并完成了发布。我所做的只是“传达方向”和“确认结果”。

为什么我不选择 Note、WordPress 或 X（旧 Twitter），而是选择在这样一个静态网站上开始写博客？答案很简单：使用 AI Agent 之后，更新自己的网站比在社交媒体上发帖还要轻松。而且还有一个原因：自己网站的内容可以作为 SEO 资产不断积累——这是一个虽然低调但确实有效的长期战略。

【体验】社交媒体发布的“疲惫感”与 Antigravity 的引入

在 2026 年的今天，利用 AI 写代码或写文章已经不再是什么稀奇事。只要打开 ChatGPT 或 Claude 这样的 Web 应用，任何人都能得到还不错的成果。

然而，对于没有 IT 背景的个人开发者来说，面临的最大障碍并非 AI 的“回答”本身，而是在将这些回答反映到自己的项目中时的“摩擦”。

回想起来，从去年（2025 年）左右开始，在 VSCode 中使用 GitHub Copilot 或 Gemini 的環境就已经很成熟了。即使在使用像 Ren'Py 这样的游戏引擎进行开发时，AI 提议代码后续部分的体验也确实非常便利。

但这仅仅是“编辑器内的辅助”。自己创建文件、复制粘贴 AI 的回答、保存、使用 Git 管理、部署……这段 AI 与本地文件之间的无形之墙，对于 IT 门外汉来说依然很高，更重要的是，它非常繁琐。

转机发生在 2026 年 2 月到 3 月期间。我在为早川 SF 征文大赛创作小说时引入了 AI Agent“Antigravity”。

在那次体验中，我感受到了 Web 应用版 AI 绝对无法提供的“上下文维持能力”。不需要逐一复制粘贴过去的资料，AI 也不会丢失对项目全局的把握。AI 可以在我的仓库中自由穿梭、读取资料并更新构思草案。

“AI 能在我的电脑里自主读取、创建和更新资料及脚本，这感觉太棒了。虽然也有点可怕（笑）”

更具革新性的是，这个 Agent 可以“像人类一样操作浏览器（Chrome）”。它不仅仅是联网搜索，必要时它会亲自启动浏览器、巡回站点、获取信息并将其整合到项目中。这是拥有“手脚”的 Agent 特有的领域，是 Web 应用版 AI 无法企及的。

Of course, this isn't a "magic bullet" that solves everything. AI context maintenance still has limits, and human "rein-handling"—giving appropriate instructions each time and having it read necessary materials—is essential. I also use various AIs like web app versions and NotebookLM according to the purpose.

However, by placing Antigravity at the "center" of the project, the vast amount of time previously spent on copy-paste work has undoubtedly shifted toward more essential trial and error.

【发现】反转现象：更新自建站比发社交媒体更“轻松”

小说投稿之后，我转入了目前正在制作的悬疑游戏《神屋侦探事务所》的项目中。在这里，我也遇到了惊喜。

通常，信息发布的主流是 Note 或 X。然而对于不擅长写作的我来说，面对外部平台的发布界面进行复制粘贴和排版，是一件意外地让人感到压力的事情。

但在 Antigravity ✕ GitHub Pages 的环境下呢？只需要在聊天窗口里跟 AI 说一句：“把这次开发的感悟写成文章，按平时的模板发布一下。”AI 就会直接生成 HTML、整理目录、推送并发布到全世界。

“利用 AI 更新自己的网站，比复制粘贴到外部社交媒体要轻松得多。”这种不可思议的反转现象发生了。

【本质】为什么 GitHub Pages ✕ AI 是最强组合

为什么现在要选择 GitHub Pages？原因在于这个平台的“简洁性”与 AI Agent 的特性完美契合。

如果想把传统的托管服务或 CMS（如 WordPress）交给 AI，登录、填写表单、管理数据库或 FTP 传输等复杂步骤就会成为障碍。这些设计的前提是“人类通过浏览器进行操作”，对 AI 来说反而难以处理，且存在破坏系统的风险。

然而，GitHub Pages 的“发布”行为被高度统一为一点：“Git push”。

创建文件、放入文件夹、提交并推送。对于 AI Agent 来说，这只是它最擅长的“文件操作”の延伸。操作的抽象程度被提升到了极限，其结果就是对 AI 而言，“编辑仓库”比“操作管理界面”要安全、快捷得多。

我们要做的仅仅是在聊天中下達指令：“更新这篇文章。”AI 就会在后台完成写作、生成图像、排版 HTML 并完成推送。原本繁琐的“博客更新”日常，就这样从意识中消失了。这就是 AI Agent ✕ GitHub Pages 这一组合为个人开发带来的“最强发布基准”の真相。

当然，这并不全是玫瑰色的愿景。例如 Steam 商店的多语言支持，即使我有 18 种语言の JSON 数据，最终还是得面对 UI 上庞大的输入项目进行“复制粘贴地狱”。虽然利用 Antigravity の浏览器操作功能或许可以实现自动化，但像商店设置或 X 发布这样稍有差池就会导致“事故”的核心部分，人类心理上の刹车——觉得完全交给 AI 还是有些“可怕”——也是目前开发環境中の真实写照。

【SEO】自建站内容将作为“资产”不断积累

在静态网站上运营博客还有一个隐藏的意图：自建站的内容会直接转化为 SEO 资产。

发在 Note 或 X 上的帖子随时可能因为平台的变动而消失。算法一变曝光量就会骤减，服务一停一切都会归零。但是，在自己域名下积累的内容会随着时间推移獲得 Google 更高の评价，并成为通过搜索流入の稳定入口。

这篇文章本身就是这个实验的第一步。如果它能逐渐通过“AI Agent”、“GitHub Pages”、“个人开发”等关键词被搜索到……这就是一种虽然缓慢但确实有効の积累戦略。关于 Steam 审核应对和 18 语言本地化等深度话题，我计划在后续文章中詳細阐述。

【结论】AI 成为“项目的共同开发者”

作为一个没有专业 IT 知识の人，能够进行 18 种语言的游戏制作以及极速构建現代化の网站，这完全是因为我能将 AI 不仅仅作为“辅助”，而是作为“共享项目并处理具体实務の最强工具”来徹底使用。

当然，让 AI 自由触碰电脑里の文件确实存在风险和恐惧感。人类需要“握好缰绳”，比如在 GitHub 上管理历史记录，或者在不同系统中做好备份。然而，这里所拥有的速度感足以弥補这些恐惧。AI 已经打破了技術の壁垒，現在我所集中の只有“下一步如何让项目更有趣”の决策。如果你已经开始厌倦与 AI 之間の复制粘贴工作，或者因为自己是“IT 门外汉”而犹豫不決，我強烈建議你現在就邀請一个 Agent 进入你の仓库。在那里，一个比你想象中更自由、且“不孤独”の个人开发未来正等待着你。

“虽然太依赖 AI 反而可能会变得孤独就是了（笑）”
